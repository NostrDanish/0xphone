# Licensing, upstream relationships & branding

Open source is a licensing and governance commitment — not merely publishing source.

| Project / component | Proposed treatment |
|---|---|
| AOSP | Track applicable Apache 2.0 and component-specific licenses |
| GrapheneOS | Review individual repository licenses, notices, and contribution terms before reuse |
| Omarchy | Inspected repo includes an MIT license; verify exact revision and every dependency before redistribution |
| Ubuntu Touch | Audit relevant source components, porting stack, kernel, third-party licenses |
| Linux kernel | Preserve GPL obligations and corresponding-source requirements |
| Firmware / proprietary blobs | Review redistribution terms; OS licensing does not grant blob redistribution rights |
| AI models | Track model weights, inference code, training-data disclosures, and model-specific usage restrictions separately |
| Third-party libraries | Maintain an SBOM, license inventory, and attribution notices |

These are preliminary directions, not a substitute for release-specific legal review.

## Branding

Use a new project identity. Do not imply 0xPhone is an official GrapheneOS, Omarchy,
or Ubuntu Touch product. Review trademark rights before using those names or logos in
project branding.
